WAVE PROOF OF LIFE (4c765a5, tag wave/proof-of-life)
  Decode step batched over 2B lanes. MAGPIETTS_WAVE_PROBE=B replicates the
  live item into B slots to measure step cost against batch.

  B    decoder ITL   work   time
  1      1.55 ms      1x    1.00x
  2      1.61 ms      2x    1.04x
  4      1.81 ms      4x    1.17x
  8      2.00 ms      8x    1.29x

  Item 0 bit-identical at frame 0 for every B (line and paragraph); first
  difference always frame 1+; B=2 line same length. Step-0 exactness is the
  gate, not a file hash -- batching changes the matmul kernel, which changes
  the last bits, which flips a greedy argmax.

  Implication: 8 chunks decoded together cost 2.00 ms/step against 8 x 1.55
  = 12.4 ms sequentially, i.e. ~6.2x less decoder time per chunk. Real gain
  bounded by the codec (RTFx ~70 = RTF 0.0143) and by chunk availability.

  NOT the wave yet: no scheduler, no per-item text, no per-item cross-KV,
  LT still single-item. Probe does B x work for one output so its RTF rises.

  history      audio      RTF      sha256

  Pinning at 20 reproduces the adaptive output byte for byte here. The
  adaptive path only diverges when required_history exceeds default_history
  = min(prior_tokens, current_tokens, 20, max_history), i.e. when a chunk
  under-attends and the next needs a longer window to recover. So the wave's
  semantic cost is zero on inputs where that never happens, and pinning at 20
  is the setting that preserves current behaviour.

  --tts.batch-size > 1 refuses without a pinned history rather than silently
  falling back. Defaults (batch 1, adaptive) are bit-identical to S3.
